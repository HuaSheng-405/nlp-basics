# BERT vs GPT:为什么一个能理解、一个能生成

本人最近看了Transformer,GPT,和BERT的论文,并手写了Transformer,微调了BERT,用GPT跑了生成实验,想写一篇技术博客来作为这几天的产出,把知识点串起来,于是有了这篇文章.

BERT和GPT作为Transformer出现后,NLP(自然语言处理)领域相当热门的两个语言模型,各自有自己出彩的地方——BERT擅长语义理解,在文本分类,问答,情感分析等任务上大放异彩.而GPT则擅长文本生成,在文本续写,翻译等任务上表现突出.是什么导致它们出现如此差异?为什么一个能理解,一个能生成?

## 一、架构差异

BERT采用的是Transformer中的Encoder架构,而GPT则是Decoder-Only架构.Decoder的注意力层中会采用causal mask(因果掩码),这里用我手写的一个Transformer中的代码作解释.

```
causal_mask = torch.triu(torch.ones(seq_len,seq_len,device=x.device),diagonal=1).bool()
```

而计算注意力时,  Q×K的掩码情况可以以下表来表示:

|      | K1   | K2   | K3   | K4   |
| ---- | ---- | ---- | ---- | ---- |
| Q1   | 1    | -∞   | -∞   | -∞   |
| Q2   | 1    | 1    | -∞   | -∞   |
| Q3   | 1    | 1    | 1    | -∞   |
| Q4   | 1    | 1    | 1    | 1    |

正好对应了代码中的上三角矩阵,后续将score矩阵中对应掩码矩阵元素为True的位置全部设置为-∞即可.

由于causal mask,使得GPT在训练时只能看到前面的词,因此模型学习到了在不清楚后面的词的情况下,生成输出.而BERT采用的Encoder架构不存在causal mask,模型可以轻松看到所有的词,学习到句子的含义.以下是Encoder层的前向传播过程,可以看到mask设置为了None.

```
def forward(self,x,mask = None):
        #1.子层1 self-attention + add & norm
        attention = self.my_attention(x,x,x,mask)
        x = self.norm1(x + self.dropout(attention))

        #2.子层2 ffn + add & norm
        ffn_output = self.ffn(x)
        x = self.norm2(x + self.dropout(ffn_output))

        return x
```

## 二、训练目标差异

BERT的训练任务是MLM,而GPT的训练任务是续写.GPT给定一个输入prompt后,要接着这段话生成文本,GPT的Decoder-Only架构天然决定了它适合这一类任务.而BERT的训练任务类似于完形填空,研究者把输入语句的随机15％的词用mask掩码,让模型猜测被掩码的词是什么,只有真正理解了整句话的意思,才能正确的猜测出要填的词.至此,GPT通过续写学会了生成,BERT通过完形填空学会了理解.

## 四、自回归的重复性问题

从上面的生成结果可以看出,贪心解码和beam search都容易陷入重复的死胡同.观察Qwen的生成结果,贪心解码直接掉进了选择题的模式,这是因为Qwen的训练数据里选择题太多.这一现象同时反应了确定性解码会被模型训练数据中最高频的模式"拽走".而top_k和top_p这种带有随机性的采样策略则不容易出现这个问题,并且生成的文本具有一定的多样性.现在所有的LLM推理时都用采样策略而不是纯贪心——确定性解码的死循环问题无解。

## 五、总结

BERT(Encoder架构)重理解,适合文本分类,情感分析等需要理解语义的任务.GPT(Decoder架构)重生成,适合完成文本续写,翻译等任务.而现在的大模型采用Decoder-Only + RLHF,同时具备理解和生成能力,功能较之先前的模型更加强大.
