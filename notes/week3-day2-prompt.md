# Prompt Engineering 对比实验

  ## 实验配置

  - 模型：Qwen2.5-0.5B
  - 问题：什么是强化学习
  - max_length：200，do_sample=True，top_p=0.9，temperature=0.7

  ## 三种策略对比

|          | Zero-shot                                 | Few-shot (2 examples)                        | Chain-of-Thought             |
| -------- | ----------------------------------------- | -------------------------------------------- | ---------------------------- |
| Prompt   | 直接提问，不加任何引导                    | 给两个 Q&A 样例，再问目标问题                | 要求按"步骤1/2/3"逐步回答    |
| 输出质量 | 不稳定——0.5B 小模型容易偏题，输出党史考题 | 格式正确但停不下来——模型进入"生成问答对"循环 | 三步骤结构完整，逻辑连贯     |
| 优点     | 最简单，零 prompt 成本                    | 格式正确时可以精准控制输出风格               | 结构化轨道约束模型，不宜偏题 |
| 缺点     | 小模型极不稳定，大模型才靠谱              | 小模型容易把样例当成"续写模板"而非"回答指导" | prompt 设计成本最高          |
| 适用场景 | 强模型 + 简单任务                         | 需要统一输出格式                             | 需要推理步骤的复杂任务       |
  ## 实验现象

  **Zero-shot 翻车：**
  模型在 0.7 temperature 下被训练数据最高频的模式（考试题）拉走了注意力。

  **Few-shot 格式正确但停不下来：**
  模型看到两个 Q&A 样例后，学会了"Q:...A:..."格式，于是开始给自己出题——"Q: 什么是迁移学习？Q:
  什么是自然语言处理？"一直问下去。

  **CoT 最稳定：**
  三个步骤写死了解空间，模型被卡在既定框架内执行，既不会跑题也不会失控。

  ## 结论

| 模型大小 | 推荐策略                                                     |
| -------- | ------------------------------------------------------------ |
| < 1B     | CoT > Few-shot > Zero-shot                                   |
| 1B-7B    | Few-shot ≈ CoT > Zero-shot（用 few-shot 样例末尾加 stop 指令） |
| > 7B     | Zero-shot 已可行，Few-shot 用于统一格式，CoT 用于推理任务    |
