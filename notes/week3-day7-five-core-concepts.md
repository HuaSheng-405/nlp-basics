# 从 Token 到 RAG：LLM 应用开发者必须知道的 4个核心概念

## 1. Token — 模型不认字，只认识数字

人工智能的组成是算法、算力和数据.而token无疑是数据里绕不开的一环.我们知道,计算机底层只认识0和1,那么我们平时输入给大模型的问题,是怎么从文字转变成数字的呢?答案就是通过token,翻译成中文叫做词元.对于中文,token长这样:"我爱自然语言处理" ->"我" "爱" "自" "然" "语" "言" "处" "理".每个字是一个token.

```python
tokenizer = AutoTokenizer.from_pretrained("bert-base-chinese")
tokens = tokenizer.tokenize("我爱自然语言处理")
print(f"分词结果:{tokens}")

分词结果:['我', '爱', '自', '然', '语', '言', '处', '理']
```

而对于英文,则有所不同.我们用bert-base-uncased模型切词,英文的token长这样:"playing" -> "playing" "unbelievably" ->'un', '##bel', '##ie', '##va', '##bly'对于playing这种高频词汇,会被bert存为一个整体,而unbelievably这种生僻词,则会被拆成子词拼接.

```python
tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")
print(tokenizer.tokenize("playing"))     
print(tokenizer.tokenize("unbelievably"))

['playing']
['un', '##bel', '##ie', '##va', '##bly']
```

那么我们输入给模型的文字,首先会被分词器,拆分成一个个的token,然后根据词表编码成数字——每个模型内部都会记录一个词表,大小在1万到15万不等,本质是一个字典,记录了一个个token和它对应的编号.因此模型只需要查表就可以把token列表转换为一个向量,接下来这个向量中的每个token会被词嵌入层转换为一个嵌入向量.接下来就可以交给模型进行处理了.

```python
self.embedding = nn.Embedding(vocab_size,d_model)
```

## 2. Attention — 模型怎么"读懂"上下文

Attention也叫注意力机制,它的作用是使模型捕获一句话中词与词之间的关系.这使得模型在处理句子中的每个词时,这个词不仅仅包含其本身的信息,还包含着这个词在上下文中的角色信息.通过计算注意力,模型可以轻松的知道这个词在这句话中扮演了一个什么角色,它与句子中的其他词有什么联系,这个能力对于模型学习语义起到了至关重要的作用.Attention的计算公式如下:

 ![Attention(Q,K,V)=softmax(\frac{Q\times K^{T}}{\sqrt{d_{k}}} )\times V](https://www.zhihu.com/equation?tex=Attention(Q%2CK%2CV)%3Dsoftmax(%5Cfrac%7BQ%5Ctimes%20K%5E%7BT%7D%7D%7B%5Csqrt%7Bd_%7Bk%7D%7D%7D%20)%5Ctimes%20V) 其中Q,K,V是由输入的词嵌入input分别乘以 ![W^{Q}](https://www.zhihu.com/equation?tex=W%5E%7BQ%7D) , ![W^{K}](https://www.zhihu.com/equation?tex=W%5E%7BK%7D) , ![W^{V}](https://www.zhihu.com/equation?tex=W%5E%7BV%7D) 权重矩阵得到的,分别代表查询向量,键向量和值向量.句子中的每个词计算对其他词的注意力,词与词的注意力权重高了,语义就传过来了.Attention的代码计算过程如下:

```python
scores = (query @ key.transpose(-2,-1)) / math.sqrt(self.d_k)
#加入mask掩码机制
if mask is not None:
        scores = scores.masked_fill(mask,float('-inf'))
attention = self.softmax(scores) @ value
```

值得注意的是,在模型生成时,内部会通过causal mask(因果掩码)屏蔽掉当前生成的词之后的词,防止模型提前看到未来的信息,causal mask其掩码矩阵代码实现如下:

```python
causal_mask = torch.triu(torch.ones(seq_len,seq_len,device=x.device),diagonal=1).bool()
```

causal mask过程可以用一张表格表示:

|      | K1   | K2   | K3   | K4   |
| ---- | ---- | ---- | ---- | ---- |
| Q1   | 1    | -∞   | -∞   | -∞   |
| Q2   | 1    | 1    | -∞   | -∞   |
| Q3   | 1    | 1    | 1    | -∞   |
| Q4   | 1    | 1    | 1    | 1    |

模型在自回归时,第一轮只能看到K1,第二轮只能看到K1和K2,以此类推.这一特性也解释了为什么BERT是双向的,GPT是单向的——causal mask只存在于decoder里,而BERT采用的是Transformer的Encoder架构,GPT采用的是Decoder-Only架构.

## 3. Prompt — 用户跟模型之间的"语言"

prompt提示词,即用户输入给模型的话.对于同样的模型,不同的prompt,输出天差地别.可以采用以下几种策略来提高模型的回复效果.

|          | Zero-shot(零样本)            | Few-shot (少样本)                            | Chain-of-Thought(思维链)            |
| -------- | ---------------------------- | -------------------------------------------- | ----------------------------------- |
| Prompt   | 直接提问，不加任何引导       | 给两个任务样例，再问目标问题                 | 要求模型按"步骤1/2/3"逐步思考并回答 |
| 优点     | 最简单，零 prompt 成本       | 格式正确时可以精准控制输出风格               | 结构化轨道约束模型，不宜偏题        |
| 缺点     | 小模型极不稳定，大模型才靠谱 | 小模型容易把样例当成"续写模板"而非"回答指导" | prompt 设计成本最高                 |
| 适用场景 | 强模型 + 简单任务            | 需要统一输出格式                             | 需要推理步骤的复杂任务              |

同时我们可以通过修改prompt来提高模型结构化输出的能力,采用Qwen2.5-0.5B模型使用3种不同prompt结构化策略的生成样例如下:

## 4. RAG — 让模型"读到"它没学过的知识

假设你的模型训练于2024年,那么2024年之后发生的事情,模型是不知道的.一些公司内部的私密信息,模型也是不知道的.这带来了很大的不便,我们可以使用RAG——检索生成技术来解决这一问题.来看代码:

```python
documents = SimpleDirectoryReader('./data/llama_test').load_data()	  #一行加载
index = VectorStoreIndex.from_documents(documents) 					 #一行建索引
retrieved = index.as_query_engine().retrieve("什么是 Transformer?")	#一行检索
```

在这里我采用了Llama Index框架,首先加载我们的文档,文档中有各种包含知识的文件,SimpleDirectoryReader会读文档,并调用合适的Reader对象读取文档中的文件,将文件中的文本和文件信息封装成一个Document对象.因此,通过第一行代码我们得到了一个包含多个Document对象的列表.

然后就是第二行代码,这行代码的作用是将每个Document对象中的文本转换成向量,并以(文本,向量)对的形式存入向量数据库中.这里我没有配置向量数据库,默认会用numpy数组存储.此时我们的"知识库"就已经建好了.值得一提的是,如果我们设置了文档切片,在这一步最开始程序会先把Document切成一块块的chunk(文档片段),这是为了防止文档中的文本过长导致挤占上下文窗口或者有效文本与无关文本绑在一起导致检索粒度太粗.

接着来到第三行代码,它的作用是检索我们的"知识库",通过计算余弦相似性筛选出与问题最相关的几个文档片段,然后将这些片段拼接进prompt里,这样以来大模型就可以根据筛选出的知识来回答用户的问题,减少了模型幻觉的出现.
